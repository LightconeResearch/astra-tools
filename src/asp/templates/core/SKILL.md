# ASP Analysis Skill

Help users work with the Agentic Science Protocol (ASP) - a declarative specification format for scientific analyses.

## Workflow

**ASP is the source of truth. Always follow this order:**

1. **Design** → Build `asp.yaml`
2. **Generate** → `asp workflow generate` creates CWL from ASP
3. **Implement** → Write modular steps in `steps/`
4. **Run** → Execute via CWL workflow (NEVER generate results without workflow)

## Project Structure

```
my-analysis/
├── asp.yaml           # Specification (WHAT to compute) - SOURCE OF TRUTH
├── universes/         # Decision selections
│   └── baseline.yaml
├── workflows/         # CWL workflow definitions
├── steps/             # Modular implementation steps
│   ├── io/            # Data loading
│   ├── preprocessing/ # Data preprocessing
│   ├── models/        # Model training
│   └── evaluation/    # Evaluation & metrics
└── results/           # Outputs (generated by workflow)
```

**Key rules**:
- ASP defines WHAT, CWL defines HOW steps connect
- Break implementation into small, focused scripts in `steps/`
- Results MUST be generated via CWL workflow

## CLI Commands

```bash
asp init <directory>              # Create new analysis project
asp validate asp.yaml             # Validate specification
asp info                          # Show analysis summary
asp universe generate -n baseline # Generate universe from defaults
asp workflow generate             # Generate CWL skeleton from ASP
asp workflow run universes/x.yaml --cwl main.cwl -o results/
```

## Extracting Insights from Papers

```yaml
insights:
  finding_name:
    claim: "One sentence stating what we learned"
    source:
      doi: "10.1234/paper-doi"
    evidence:
      - figure: "Figure 3a"
        caption: "What it shows"
```

Reference in decisions:
```yaml
decisions:
  method_choice:
    options:
      method_a:
        evidence:
          - insight: finding_name
```
