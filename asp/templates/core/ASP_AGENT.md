# ASP Agent

Help users design and execute ASP (Agentic Science Protocol) analyses.

## Project Structure

```
my-analysis/
├── asp.yaml           # Specification (WHAT to compute) - SOURCE OF TRUTH
├── universes/         # Decision selections
│   └── baseline.yaml
├── workflows/         # CWL workflow definitions
│   └── main.cwl
├── steps/             # Modular implementation steps
│   ├── io/            # Data loading
│   ├── preprocessing/ # Data preprocessing
│   ├── models/        # Model training
│   └── evaluation/    # Evaluation & metrics
└── results/           # Outputs (generated by workflow)
```

## Workflow

**ASP is the source of truth. Always follow this order:**

1. **Design** → Build `asp.yaml`
2. **Generate** → Create CWL skeleton from ASP
3. **Implement** → Write modular steps (not one giant script)
4. **Run** → Execute via CWL workflow (NEVER generate results without workflow)

---

## Phase 1: Design (Interactive)

Help the user create `asp.yaml`:

1. **Understand the problem**: What research question are they answering?
2. **Identify inputs**: What data do they have?
3. **Define outputs**: What results do they need?
4. **Map decisions**: What methodological choices exist?

Write `asp.yaml` incrementally. Validate with `asp validate asp.yaml`.

When complete, generate a baseline universe:
```bash
asp universe generate -n baseline
```

---

## Phase 2: Generate CWL (Automatic)

Once `asp.yaml` is ready, generate the CWL workflow skeleton:

```bash
asp workflow generate
```

---

## Phase 3: Implement (Autonomous)

Break implementation into modular steps in `steps/`:

```
steps/
├── io/load_data.py           # Load and validate inputs
├── preprocessing/clean.py    # Data cleaning/transforms
├── models/train.py           # Model training
└── evaluation/metrics.py     # Compute output metrics
```

Each step is a small, focused script. The CWL workflow chains them together.

---

## Phase 4: Run (Always via Workflow)

**NEVER generate results directly. Always run through the CWL workflow:**

```bash
asp workflow run universes/baseline.yaml --cwl workflows/main.cwl -o results/
```

---

## CLI Commands

```bash
asp validate asp.yaml              # Validate specification
asp info                           # Show analysis summary
asp universe generate -n baseline  # Generate universe
asp workflow generate              # Generate CWL from ASP
asp workflow run universes/baseline.yaml --cwl workflows/main.cwl -o results/
```

## Key Principles

1. **ASP is source of truth** - CWL is derived from ASP
2. **Always run via workflow** - Never generate results directly
3. **Modular steps** - Break work into small, focused scripts in `steps/`
4. Work autonomously - implement without excessive asking
